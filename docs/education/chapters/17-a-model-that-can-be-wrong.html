Chapter 17

A Model That Can Be Wrong

If some of your numbers were chosen so the answer would come out right, then getting the right answer proves nothing. So how do you build a model that is allowed to lose?

~16 min read 5 interactives 1 table

By the end you will be able to

  • Explain why matching a target that your inputs were fitted to is not evidence about nature.
  • Say what a held-out observable is, and why this project's honest list of them is short.
  • Take any claim and name the result that would have refuted it — and spot the claims where no such result exists.
  • Explain why building a fallback first is what made it safe to run an experiment the project might lose.

The answer was already in the question

Chapter 16 sorted every number that goes into the solver by where it came from. Four bins: measured, fitted, numerical, and one more. The project calls that fourth one P3, and it is the subject of this chapter. The project's parameter file defines it like this:

“P3 — Nakaya-informed SDAK hypotheses. The narrow-facet dip locations/depths were chosen to impose agreement with the morphology diagram (monograph printed p. 152 / pdf 153: ‘I have chosen different values of T_onset for the basal and prism facets to impose agreement with the known ice-growth behaviors from the Nakaya diagram’). Any Nakaya comparison using P3 inputs is in-sample reproduction, never independent validation.”
snowflake repository, docs/libbrecht-parameters.md — “Provenance classes”

SDAK stands for structure-dependent attachment kinetics: Libbrecht's proposal that how easily a face grows depends not only on temperature but on how wide that face is. Narrow faces grow more easily, which makes them narrower still — a feedback the charter describes as producing “thin plates, sharpening edges, and hollow columns” (project charter.md, §2.5). It is a hypothesis, not a measurement, and the “narrow-facet dips” in the quotation above are how it would enter the model.

Now read that quoted sentence slowly, because it is doing something unusual. It is the author of the physics telling you, in print, that he picked those values so that the model would agree with the diagram. That is not cheating and it is not hidden. It is a completely normal way to build a model when the measurements you would need do not exist yet. But it has a consequence that is easy to miss and impossible to undo.

If a number was chosen to make the model agree with the Nakaya diagram, and you then run the model and it agrees with the Nakaya diagram, you have learned nothing about snow. You have learned that the choosing worked. The answer was inside the question. Statisticians call this an in-sample result: the thing you are testing against is part of what you built with. The opposite is held-out — you test against something nobody consulted while building.

Key idea

Agreement is only evidence if disagreement was possible. A target your inputs were fitted to cannot supply that possibility, no matter how carefully you run the test.

The project's charter states the consequence as a rule rather than as an opinion: “SDAK-bearing inputs are provenance class P3 (§2.7), and any Nakaya comparison that uses them is in-sample reproduction, not independent validation” (project charter.md, §2.5). And in the standing guardrails: “Results from Nakaya-informed (P3) inputs are never labeled independent validation, and no-SDAK and SDAK results are never merged in a report” (§3.3).

The next demo hands you the two knobs the quotation is about. They are real — the centres of the two dips in the published attachment model — and moving them changes which face of the crystal is easier to grow. Try to make the model match nature. It is not hard.

Tuning felt like discovery, and it produced a number that looks exactly like a result. It is not one. Notice, too, what you could see the whole time you were dragging: the score. Chapter 27 is about what changes when you cannot.

There is an obvious-looking escape from all this, and the project considered it and wrote down why it does not work. If the problem is that someone might tune the knobs to fit, why not simply promise not to touch them, in advance, in public?

“Keep Phase 6 as-is and rely on pre-registration. Rejected: freezing a leaked input freezes the leak. Pre-registration binds future hands; it cannot unknow what the SDAK curves were built from.”
snowflake repository, docs/decisions/0005-validation-scope-surface-operator-numerics.md — “Alternatives considered”

That is the sharpest sentence in the whole decision record. Promising not to cheat from now on does nothing about information that is already inside your inputs. The leak happened before you arrived. Read the rejection narrowly, though: it says pre-registration cannot fix this. It remains the right tool for the other half of the problem — the half where someone might tune afterwards — which is why chapter 27 is about it, and why this chapter ends by asking you to seal an envelope of your own.

How big is the borrowed piece

A fair objection: maybe the diagram-informed part is a tiny correction, and the rest of the model is doing the real work. So how big is it?

The parameter file records the two dips as digitized readings off a printed figure, sized relative to the broad-facet curve at the same temperature. A “broad facet” is an ordinary wide flat face; the dips describe what the model does differently on a very narrow one.

The two σ0 dips — the mechanism the parameter file labels SDAK-1 — transcribed from docs/libbrecht-parameters.md §4.1, where each row is recorded as a digitization of the monograph's Figure 4.12. Every row is provenance class P3.
Facet Dip minimum, σ0
how much spare vapour a facet needs before a new layer can start — smaller means easier		 At Size of the dip What the source says it explains
narrow basal 0.07–0.08% −4 to −4.5 °C ×6–7 lower rapid basal growth of hollow-column edges near −5 °C
narrow prism 0.18–0.20% −14 to −16 °C ×15 lower thin-plate edges near −15 °C

A factor of fifteen is not a correction. At the bottom of the prism dip the model is being told that a narrow prism face needs fifteen times less spare vapour before a new layer can start than the measured broad-facet curve says. And σ0 is not itself a speed: it enters the growth law inside an exponential — the attachment coefficient is A · exp(−σ0 / σsurf), with σsurf the spare vapour actually reaching the surface (docs/libbrecht-parameters.md §1, citing 1910.09067 Eq. 3) — so dividing it by fifteen does not make the face grow fifteen times faster. The effect is exponential in that ratio, and wherever the surface is starved enough for nucleation to be the bottleneck at all, it is far larger than fifteenfold.

The source is also explicit that the dips are a proposal rather than a measurement. They are drawn dotted in the original figure “to signify their substantial uncertainties”, and a companion paper says plainly that “Neither the width nor depth of the dip structure … is well constrained by measurements” (both recorded at docs/libbrecht-parameters.md §4.1).

How we know

The parameter file records two SDAK hypotheses, not one. SDAK-1 is the pair of σ0 dips in the table above. SDAK-2 changes a different quantity on narrow prism facets above about −10 °C and is aimed at sharp-tipped dendrites rather than at the habit flip; it is written down but not digitized, because nothing in the solver consumes it. Of both, §4 says: “Nothing in the solver implements either one — SDAK appears in no source file — so every run to date is a no-SDAK run.” That is a claim you can check by searching the repository, which is the point of writing it that way.

So the project has a clean option most modelling projects do not: run the comparison with the diagram-informed pieces removed entirely. Then a Nakaya comparison is a real test, because the inputs no longer contain the answer — though the project still refuses to call it independent validation. Decision 0005 reserves that phrase for the held-out observables in the next section, and gives this run a different name instead: the no-SDAK probe “becomes a first-class scientific result in its own right: does the measured large-facet crossing alone produce any habit reversal? Either answer is publishable within the project's own terms.” That is the run chapter 28 reports, and decision 0005 registered it in advance, both outcomes included.

Two experiments, one of which cannot fail

The in-sample trap is not only about borrowed parameters. You can build a whole experiment that cannot fail, out of entirely honest parts, and this project nearly did.

The original plan was to sweep the inherited lattice model's abstract knobs and label the resulting atlas of shapes afterwards. The charter's verdict on it is one sentence: “That fits a curve; it does not close a loop.” (project charter.md, §2.7.)

The reason is worth being precise about, because “it fits a curve” sounds like a complaint about accuracy and is not. The inherited lattice model contains no temperature anywhere. The decision record spells out what follows:

“With G–G's knobs, Phase 6 is curve-fitting. Sweep the parameter space, measure the morphologies, paste a temperature axis onto the resulting atlas. G–G's solver contains no temperature at all. You can reproduce the shapes on both sides of the Nakaya flip without reproducing the reason for it, and when asked ‘why does it return to plates at −15 °C,’ the only honest answer is ‘because a knob was tuned until it did.’”
snowflake repository, docs/decisions/0003-libbrecht-attachment-kinetics.md — Context

The next demo is that argument with the handles left on. Two modes, one screen. In the first, the model has three knobs with no physical meaning, and you also decide afterwards which temperature each column stands for. Match the real diagram. Then match the diagram this page invented, by the same method.

In calibration mode the counter goes up for a diagram that does not exist. A method that matches an invented reference as readily as the real one has told you nothing about either. That is what “cannot fail” means in practice: there is no arrangement of the world that the method would have reported as a miss.

Validation mode is the same screen with the axis frozen and the knobs gone, because temperature now enters the equations rather than being written on them afterwards. Most columns disagree, and there is nothing to slide. Do not carry that count away as the project's answer — the banner above the strip says why it cannot be. Chapter 28 has the project's own number, measured on the real solver and counted a different way.

On 2026-07-14, before any physics code was written, the project renamed the phase that does this comparison. “Calibration atlas” became “Validation against the Nakaya diagram”, because the old framing “could not have failed, and therefore could not have taught anything” (project charter.md, §3.2, Phase 6).

The decision record that forced the rename lists what the change bought and what it cost. The last item on the cost list is one line: The model can now be wrong. Deliberately. The project filed its own falsifiability under expenses, which is exactly right — it is a price, and it was paid on purpose.

Careful

The rename is not relabelling. Under the old plan the model produced shapes and a human decided afterwards which conditions those shapes belonged to. Under the new one you set −5 °C, the number travels into the attachment equations, and whatever comes out is the answer. The charter puts the test as two questions with answers the builders did not control: “Set −5 °C — does a column grow? Set −15 °C — does the habit flip back to plates? A model that cannot be wrong is not attempting this problem.”

What a real test looks like

Ruling things out is easy. The harder question is what this project would accept as evidence. The charter names four families of held-out observable — measurements the inputs were not tuned toward:

“Independent validation runs against held-out observables the inputs were not tuned to: growth rates vs (T, σ), size-dependent habit, pressure dependence, and growth-history responses.”
snowflake repository, project charter.md — §2.7

Pressure is the cleanest of the four, because it shows what makes a target genuinely held out. How fast water vapour spreads through air is inversely proportional to pressure; that relationship is exact, it was used at one reference pressure, and nothing in the model was ever adjusted to make anything match at any other. The project's own register puts it in one line: “D ∝ 1/P is exact at reference pressure and nothing was tuned to it — a cheap, genuinely held-out axis” (docs/stretch-sharing-and-investigation.md §3, item I4).

The same register is equally plain about how many such tests are within reach today:

“practically reachable held-out set today is ~5 entries, not 122 — most sit behind the column-seed ADR”
snowflake repository, docs/stretch-sharing-and-investigation.md — §3, item I1

An ADR is one of the numbered decision records this chapter keeps quoting — the project writes them as “ADR 0003” and “decision 0005” interchangeably. The column-seed one has not been written yet. It is the pending decision about whether a run may be started from a column-shaped seed crystal and still count as evidence, and until it lands, the Phase 6 plan puts “an elongated/column seed class” on its out-of-scope list (docs/plans/phase-6-nakaya-validation.md). Most of the remaining held-out tests are waiting behind it.

Five. Written down by the project about itself, in the same paragraph where it identifies its best falsification target: a set of free-falling-crystal growth measurements whose “reported sense opposes the model's expectation — the single strongest falsification target available” — that is, the measured effect points the opposite way to what the model predicts. The strongest available test is one the project expects to lose, and it is at the top of its own to-do list. That combination is what an honest evidence ledger looks like: short, and pointed at the places that hurt.

Holding data back sounds obvious until you have to do it.

Hold nothing back and the score is perfect and meaningless. Hold back the two awkward points and the model gets them wrong, which is not a disaster — it is the first true thing the exercise has told you. A test you might fail is the only kind that reports anything.

What would have proved it wrong?

Everything in this chapter reduces to one portable question you can ask of any claim, in any subject: what result would have shown this to be false? If you cannot answer, the sentence is not a claim about the world. It might still be beautiful, interesting, or true. It just is not evidence.

The project answered that question for itself in advance and in public. Its Phase 6 entry lists what the model is expected to produce, in the charter, before the sweep existed: “Plates near −2 °C, columns near −5 °C, plates again near −15 °C, columns below −30 °C.” Four statements, each of which a run could contradict.

Two of those five have no possible refutation attached, and the seductive one is “the crystal looks like a real snowflake”. It feels like the strongest claim on the list. It is the emptiest, because nobody has said what would count as not looking like one — which is why the project's working rules ban the move outright (AGENTS.md, Rule 6).

The same discipline has a quieter version, and it constrains numbers the project genuinely produced. Before you can score a model you have to choose settings — where a threshold sits, how big the domain is — and those come from exploratory runs. The Phase 6 plan puts such runs in a separate tier of truth:

“Threshold values land from calibration probes, and those probes are not evidence. … A probe's printed metrics are never citable as a gate result.”
snowflake repository, docs/plans/phase-6-nakaya-validation.md

A run used to choose a setting cannot later be quoted as proof the setting was right. So the project keeps two classes of run, and prints the label on the probe when it is created rather than when someone needs a supporting number.

Why a fallback made the risk affordable

Here is the part that is about people rather than logic. Designing an experiment you might lose is easy on paper. Running it is hard when losing means you have nothing to show for a year of work. Under that pressure, honest people start finding reasons why the awkward points do not really count.

The project removed the pressure before it started, by building a working crystal first and refusing to delete it. The inherited threshold rule — the one with no temperature in it — stayed in the codebase permanently as a second implementation behind the same interface. It grows a beautiful crystal. It always will, whatever the physics does. The charter is explicit that this is a scientific decision and not a nostalgic one:

“That floor matters: the hybrid genuinely might not reproduce the Nakaya flip, and this project is meant to produce a delightful artifact regardless of whether it also produces a scientific result.”
snowflake repository, project charter.md — §3.2, Phase 2a

Read alongside the decision that introduced the risk, the pairing is deliberate. Under “What it forecloses”, ADR 0003 answers: “Nothing, because GGThreshold survives. If LibbrechtKinetics fails to reproduce the Nakaya flip, the project still has a working, beautiful crystal to ship …” The risky experiment was made affordable by building the consolation prize first.

Key idea

If a project can only survive one outcome, it will find a way to report that outcome. Guaranteeing a decent result whichever way the science lands is not a comfort blanket; it is what keeps the science reportable.

With the floor in place, the charter can afford to state the losing case as a normal outcome rather than a catastrophe: “A negative result is a result: if the model does not reproduce the flip, that is a finding about the model, it is reported as one, and GGThreshold still ships a beautiful crystal (Phase 2a). What is not permitted is quietly tuning until the diagram matches and calling it validation” (§3.2, Phase 6).

Your turn, before the result

Nothing here is finished, and the status is on the record rather than in anyone's head. Phase 6 — the comparison against the diagram — is marked in progress in docs/PROGRESS.md. Phase 7, the product layer this whole thing is supposed to become, is marked not started. And the run that would switch the diagram-informed dips back on has its own plan file whose status line reads “not started — blocked on ADR 0030 acceptance …”, with the outcome stated as unknown in advance: “The arm is decisive in either direction, and the direction it lands is a first either way” (docs/plans/phase-6-sdak-arm.md).

So commit. A prediction written after the result is not a prediction. Mind the asymmetry between the two questions below, because this page has to obey its own rules: chapter 14 already told you how the first one turned out, so answering it tests your memory rather than your judgement. The second one nobody can answer — not you, not the reviewers, not the project.

Still unsettled

One limitation belongs on this page rather than in a footnote. Every review this project has had — including the two-reviewer process that checked this chapter — has been a review by a language model. The project's own sharing rules say so in advance of any publication: “All reviews to date, internal and external-facing, are LLM reviews; for publication that is a disclosed limitation, not a substitute” (docs/stretch-sharing-and-investigation.md §4). The requirement they set for themselves is that at least one human domain scientist reads any manuscript before it is submitted anywhere. That has not happened yet. Nothing in this chapter should be read as having passed expert human review, because it has not.

The vocabulary is now complete. You can hold “the model was given real physics” and “the model was shown to reproduce reality” apart; you can say where a number came from; and you can tell a test from a fit. What remains is the machine that makes a failure attributable — because a model that is allowed to be wrong is only useful if, when it comes out wrong, you can tell whether the physics failed or the code did.

Which is why the project refused to write a single line of physics until the lattice underneath it had been proved on its own: a physics bug on top of an unproven lattice is two bugs wearing one coat.
